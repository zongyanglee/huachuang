# 研究流程与验收门槛

## G0：研究立项

负责人：`fiq_research_lead`

输入：用户问题、已有代码/数据/报告、时间与范围约束。

最小输出：

- 一句话研究问题；
- 可证伪的主要假设；
- 资产、市场、样本、频率和预测期限；
- 预期交付物和停止条件；
- 角色与文件所有权；
- 已知风险和关键缺口。

通过标准：问题可以被数据证伪，范围不会在开发过程中无限扩张。

## G1：证据与数据可行性

负责人：`fiq_domain_researcher`、`fiq_data_steward`

可并行开展：

- 领域研究员建立机制—证据图和制度事件清单；
- 数据管理员建立字段—来源—可得时间表，检查样本覆盖。

通过标准：

- 每个核心变量有定义、来源、单位、频率和真实可得时间；
- 证券主表可以回放历史可投资集合；
- 关键制度事件有明确生效时间；
- 缺失和异常处理不会使用未来信息；
- 数据无法支持的机制已从主要假设中删除或降级。

## G2：预分析批准

负责人：`fiq_methodology_reviewer`

在主结果出现前冻结：

- 主要、次要和探索性假设；
- 核心因子和组合定义；
- 样本内、验证集和样本外划分；
- 基准、成本、主要指标和显著性方法；
- 计划的子样本、安慰剂和敏感性检验；
- 参数搜索空间和多重检验处理；
- 失败判据与停止条件。

通过标准：方案足以约束事后解释，同时允许记录为探索性的新发现。

## G3：实现一致性

负责人：`fiq_research_engineer`

需要确认：

- 因子只使用观测时点之前可得数据；
- 信号时间、成交时间和收益区间严格错开；
- 调仓、持有、权重、缺失、并列值和极端值处理与规格一致；
- 现金、票息、到期、转股、强赎、回售和下修等事件处理明确；
- 运行参数外置，随机过程固定种子；
- 单元测试覆盖日期边界、样本资格、收益计算和事件状态转换；
- 运行能生成环境、数据、代码和配置指纹。

通过标准：测试通过，且策略规格—代码映射没有未解决差异。

## G4：统计与经济审查

负责人：`fiq_methodology_reviewer`

最低审查项：

- 样本外结果和时序稳定性；
- 自相关、异方差和横截面相关对推断的影响；
- 多重参数、多个因子和反复试验造成的数据挖掘偏差；
- 换手率、容量代理、流动性筛选和保守成本；
- 久期、信用、权益、行业、规模、价格和流动性等已知暴露；
- 极端时期、制度变化和子样本敏感性；
- 参数轻微扰动、替代定义、延迟信号和安慰剂测试；
- 统计显著性与经济意义是否一致。

可能结论：

- **通过**：主要结果在预设框架和关键稳健性检验中成立。
- **有条件通过**：结论需缩小范围或明确限定条件。
- **不通过**：证据不足、不可识别、依赖泄漏或结果高度不稳健。

## G5：冻结与独立复现

负责人：`fiq_data_steward` 负责数据冻结，`fiq_research_engineer` 负责代码与环境冻结，`fiq_replication_reviewer` 负责复现。

冻结包至少包含：

- 研究任务书和预分析方案；
- 数据清单、数据字典、快照或确定性提取说明；
- 代码提交或文件哈希；
- 完整配置、随机种子和依赖环境；
- 从空输出目录开始的运行说明；
- 预期关键表格/指标及容差；
- 已知非确定性来源。

复现者必须：

- 创建新的复现输出目录；
- 不修改冻结材料；
- 先按原说明运行，再做预定反证；
- 对每项差异给出绝对差、相对差、可能原因和影响；
- 区分数值舍入、环境差异、数据漂移和实质性逻辑差异。

## G6：报告与归档

负责人：`fiq_research_editor`

发布前检查：

- 每项核心结论能链接到具体表格、图、日志或来源；
- 报告中的样本、口径和版本与复现包一致；
- 负面结果、探索性发现和限制明确标注；
- 不把回测结果写成投资承诺或个性化建议；
- 附录包含方法、数据、稳健性和复现信息。

## 返工规则

任一门槛不通过时，建立返工单：

| 字段 | 内容 |
|---|---|
| 未通过门槛 | G0-G6 |
| 证据 | 文件、行号、表格或日志 |
| 根因 | 数据 / 定义 / 实现 / 统计 / 文档 |
| 责任角色 | 唯一修正负责人 |
| 不得改动 | 冻结或无关内容 |
| 重新验收条件 | 可客观核对的标准 |

返工后只重跑受影响阶段及其下游，不重复无关工作。
