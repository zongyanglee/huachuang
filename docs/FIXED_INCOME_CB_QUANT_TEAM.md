# 固收与可转债量化研究团队使用指南

## 已配置组件

- 团队编排 Skill：`fixed-income-cb-quant-team`
- 8 个项目级自定义 Agent：位于 `.codex/agents/`
- 项目并发上限：最多 3 个子 Agent 同时运行
- 研究模板：任务书、交接单、复现报告和正式研究报告
- 评估草案：3 个典型调用场景

该团队只用于学术研究、策略开发、回测、审查与复现，不包含实盘下单、账户连接和盘中监控。

## 最简单的调用方式

在 Codex 中直接写：

```text
使用 $fixed-income-cb-quant-team，研究可转债双低因子的样本外稳定性。
先完成研究任务书和预分析方案，经我确认后再写代码。
```

也可以只调用单个角色：

```text
请使用 fiq_data_steward 审查这个数据集的时点可得性和幸存者偏差，只输出审查报告。
```

```text
请使用 fiq_replication_reviewer 从冻结版本独立复现，不允许修改原始代码和数据。
```

## 推荐调用方式

完整研究：

```text
使用 $fixed-income-cb-quant-team 完成一个固收/可转债量化课题。
研究问题：……
资产范围：……
样本期与频率：……
可用数据：……
希望交付：研究任务书、代码、回测、复现报告和研究报告。
请按 G0-G6 门槛推进，每个门槛先汇报再继续。
```

只做审查：

```text
调用 $fixed-income-cb-quant-team 审查以下策略。
重点检查：未来函数、幸存者偏差、多重检验、交易成本和强赎/下修事件。
不要修改源文件，只给出证据、影响、严重度和整改验收条件。
```

只做研究设计：

```text
使用 $fixed-income-cb-quant-team，把这个想法转成可证伪的研究方案。
仅推进至 G2，不写代码、不运行回测。
```

## 角色名称

| Agent 名称 | 用途 | 默认写权限定位 |
|---|---|---|
| `fiq_research_lead` | 立项、分工、门槛和综合判断 | 只读/返回方案 |
| `fiq_domain_researcher` | 文献、制度、机制与来源 | 只读 |
| `fiq_data_steward` | 数据治理、审计与冻结 | 工作区写入 |
| `fiq_strategy_researcher` | 因子、信号和实验规格 | 只读/返回规格 |
| `fiq_methodology_reviewer` | 统计与偏差审查 | 只读 |
| `fiq_research_engineer` | 管道、回测、测试与环境 | 工作区写入 |
| `fiq_replication_reviewer` | 独立复现与反证 | 仅写新的复现输出 |
| `fiq_research_editor` | 正式报告与归档 | 仅写分配的报告路径 |

## 重要行为

- 主 Agent 只启动完成任务所需的角色。
- 开发者与复现者必须分离。
- 任何成果只有一个写入负责人。
- 未通过方法审查或独立复现的结果不得进入正式结论。
- 如果 Agent 没有立即出现在选择器中，重新启动 Codex 后再试。
